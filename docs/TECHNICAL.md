# 기술 문서

## 디스크 구조
- 트랙 1개(MODE2/2352). 실행 파일 `SLPM_872.86`, 게임 데이터 `DATA.FAD`.
- `DATA.FAD`는 팩의 연속입니다. 팩 머리에 12바이트 항목(오프셋·타입·크기)이 이어지고, 팩은 2048바이트 경계에 맞춰 놓입니다(`tools/fad.py`).
- 빌드는 바뀐 섹터만 다시 쓰고 EDC/ECC를 다시 계산합니다(`tools/disc.py`, `tools/cdsec.py`). 파일 크기는 바뀌지 않습니다.

## 대사
- 대사 블록은 4바이트 오프셋 표 + Shift-JIS 문자열입니다. 번역문이 길어지면 같은 팩 안에서 뒤 항목을 밀어 넣습니다(팩 끝 여유 공간 안에서).
- 가운데 정렬된 지명은 원문 앞 전각 공백 수로 중심을 계산해 전각·반각 공백으로 다시 맞춥니다.

## 글꼴
- 팩0 엔트리3(type 0x12, RAM 0x8019F800)이 12×12 4bpp 글꼴(글자당 72바이트), 엔트리4(type 0x13, RAM 0x8001F000)가 글자 코드 표입니다. 실제로 쓰인 한글을 Galmuri11로 그려 넣고 코드 0x88xx부터 배정합니다.
- 실행 파일의 글리프 전송 함수(0x80033794)를 새 함수로 점프시켜, 반각 글자를 1/4칸 단위로 전진하도록 고쳤습니다(글자 표 뒤 여유 공간에 MIPS 코드, keystone으로 어셈블).

## 그림 글자
- type 0 항목은 VRAM 원시 이미지(x, y, w, h 머리 + 데이터), 대부분 4bpp입니다(`tools/gfx.py`).
- type 5 항목은 스프라이트 표(16바이트: tpage, clut, u, v, w, h, x, y)입니다. 같은 팩과 팩0의 이미지에 적용됩니다(`tools/sprites.py`).
- `tools/gfxprev.py`가 `text/gfx_spec.py`의 사양(SPEC·WIPE·AUTO·PLATES·BLACK·VBLACK·ICONS)을 적용합니다. 글자 상자는 화면에 실제로 그려지는 스프라이트 사각형 안으로 줄여(`fit`) 잘림을 막고, 표가 없는 이미지는 원래 글자 잉크 범위 안으로 제한합니다.
- `tools/plate.py`: 나무판·종이판 위 글자를 행별 질감 보간으로 지우고 새로 그리기, 검은 바탕 글자·세로쓰기.
- `tools/logo8.py`: 타이틀 컬러 로고(8bpp, 팔레트 `text/logo_pal.json`)를 화면 좌표로 합쳐 지우고, 채움·테두리·그림자·하이라이트로 다시 그린 뒤 세 조각 텍스처에 나눠 씁니다.
- `tools/bglabel.py`: 거점 배경(8bpp, 밝기순 팔레트)에 그려진 지명판을 지우고 「기타로의 집」을 그립니다. 그림 안의 8픽셀 빈 열을 건너뛰어 화면 배치에 맞춥니다.

## 검증 도구
- `tools/emu.py`, `tools/srv.py`, `tools/c.py`: DuckStation을 백그라운드로 띄워 GDB 원격 접속으로 메모리를 읽고 쓰고, 키 입력을 자동화합니다.
- `tools/fb.py`, `tools/fbshot.py`: 상태저장에서 VRAM을 꺼내 프레임버퍼를 1:1로 저장합니다.
- `tools/sizes.py`, `tools/clipchk.py`: 문자열·그림 크기 조사.
